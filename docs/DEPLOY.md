# Deploy (about 15 minutes)

Three pieces: MongoDB Atlas (database), Render (API), Vercel (web). Nothing deploys automatically.

## 1. MongoDB Atlas

1. Create a free **M0** cluster at cloud.mongodb.com.
2. _Database Access_ → add a user with a strong password (read/write on any database).
3. _Network Access_ → allow `0.0.0.0/0` (Render free tier has no fixed IP).
4. _Connect → Drivers_ → copy the URI and add a database name, e.g.
   `mongodb+srv://USER:PASS@cluster0.xxxx.mongodb.net/specials_saver?retryWrites=true&w=majority`

## 2. API on Vercel (no card needed; alternative to Render)
1. Vercel → *Add New Project* → import this repo, **Root Directory** `apps/api` (framework: Other). `apps/api/vercel.json` and `apps/api/api/index.js` handle build and routing.
2. Env vars: `MONGODB_URI`, `JWT_SECRET`, `NODE_ENV=production`, `CORS_ORIGINS`, `AI_PROVIDER=mock` (+ optional AI vars below).
3. Deploy; `https://<api-project>.vercel.app/health` must return `{"status":"ok"}`.
4. Use `https://<api-project>.vercel.app/api/v1` as the web app's `VITE_API_URL`.

## 2b. API on Render (alternative)

1. Render dashboard → _New → Blueprint_ → pick this repo (it reads `render.yaml`).
2. Fill the prompted env vars:

| Var                                     | Value                                                                                                                                |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `MONGODB_URI`                           | Atlas URI from step 1                                                                                                                |
| `CORS_ORIGINS`                          | Your web URL, e.g. `https://specials-saver.vercel.app` (no trailing slash; comma-separate several). Set after step 3, then redeploy. |
| `JWT_SECRET`                            | auto-generated by the blueprint                                                                                                      |
| `AI_PROVIDER`                           | `mock` (default). Optional: `gemini` or `openai_compat`                                                                              |
| `AI_MODEL`, `AI_API_KEY`, `AI_BASE_URL` | Only for a hosted AI provider (see README)                                                                                           |
| `AI_DAILY_CAP_PER_BRAND`                | default `50`                                                                                                                         |

3. Deploy, then check `https://<service>.onrender.com/health` returns `{"status":"ok"}`.
4. Optional demo data: from your machine run
   `MONGODB_URI='<atlas uri>' npm run seed` (this **replaces** all data in that database; never run it on real data).

## 3. Web on Vercel

1. _Add New Project_ → import the repo.
2. **Root Directory:** `apps/web`. Framework: Vite (auto). `vercel.json` sets the SPA rewrite and CSP.
3. Env var: `VITE_API_URL` = `https://<service>.onrender.com/api/v1`.
4. Deploy. Copy the URL into `CORS_ORIGINS` on Render and redeploy the API.

## 4. Smoke test

Open the web URL → _Create your brand_ → add ingredients → log a batch → At risk → Suggest specials → Run → +1 sold → End → Dashboard.

## Notes

- The CSP allows `connect-src https:` so any API host works; tighten it to your API origin in `apps/web/vercel.json`.
- Render free instances sleep; the first request after idle takes ~30 s.
